# PRD · Модуль «Інтерактивна карта пам'яті»

**Статус:** до розробки · **Версія:** 1.0 · **Залежності:** `docs/db/schema.dbml` (`place`, `memory_route`, `memory_route_place`, `defender_place_role`), `docs/api/openapi.yaml` (тег `Places`)

## 1. Мета і межі модуля

GIS-шар платформи: місця боїв, меморіали, поховання, памʼятники та маршрути памʼяті, зв'язані з профілями захисників. Технологічна основа — **MapLibre GL JS** (не Mapbox — навмисний вибір без вендор-лока й платних API-ключів, обов'язковий для держпроєкту) + **PostGIS** + власний тайл-сервер (Martin/pg_tileserv), підтверджено дослідженням ринку 2025–2026.

**Не входить**: сама картка захисника (→ Defenders), медіа-вʼювер усередині картки місця (→ Archive).

## 2. User stories

| # | Роль | Історія |
|---|------|---------|
| M1 | Громадянин | Хочу побачити на карті меморіали свого міста і прочитати про кожен |
| M2 | Громадянин (мобільний) | Хочу, стоячи біля памʼятника, відсканувати QR і потрапити на картку місця (модель Inheart) |
| M3 | Дослідник | Хочу відфільтрувати місця боїв конкретної бригади за період і побачити маршрут на карті |
| M4 | Вчитель | Хочу показати класу «маршрут памʼяті» міста як курировану екскурсію |
| M5 | Партнер (адміністрація громади) | Хочу додати нове місце на карту через кабінет, вказавши координати і завантаживши фото |

## 3. Функціональні вимоги

### 3.1 Шари (layers)

`battle`, `memorial`, `burial`, `monument`, `museum_site`, `frontline_segment` — перемикаються незалежно чекбоксами на панелі шарів. Кожен шар — окреме GeoJSON/MVT `source-layer`, стилізований за `place.type`.

### 3.2 Кластеризація

- Використовується вбудована кластеризація MapLibre (`cluster: true`, `clusterRadius`, `clusterMaxZoom`) на базі supercluster — без власної реалізації.
- При наближенні кластери розкриваються поступово (`clusterMaxZoom` → окремі маркери).
- **Розширення:** HTML-кластери з портретом останнього доданого захисника замість числа — референс з дослідження ринку (MapLibre example «Display HTML clusters with custom properties»).

### 3.3 Пошук і фільтрація

- Фасети: тип місця, регіон (`region_id`), підрозділ (через `defender_place_role`), період (`date_from`/`date_to`).
- Синхронізація «список ↔ карта»: фільтр у списку миттєво оновлює видимі маркери (`bbox`-запит), і навпаки — панорамування карти оновлює список видимих обʼєктів.
- URL відображає стан фільтрів і viewport (`?layer=battle&bbox=...`) — можливість поділитися посиланням на конкретний вид карти.

### 3.4 Timeline-скрабер

- Слайдер дат під картою фільтрує видимі точки/лінію фронту за `date_from`/`date_to` місця — прямий референс MapLibre example «Create a time slider».
- Для `frontline_segment` — послідовна анімація зміни лінії фронту по датах (програвання з кроком, наприклад, «1 тиждень»).

### 3.5 Картка місця

Відкривається side-panel (desktop) або bottom-sheet (mobile) без переходу зі сторінки карти:

- назва, тип, опис, фото/відео з архіву;
- список повʼязаних захисників (`defender_place_role` де `place_id = X`);
- документи з архіву, привʼязані через `media_link`;
- кнопка «Прокласти маршрут» (deep-link у Google/Apple Maps через координати);
- для чутливих обʼєктів (`sensitivity_level > 0`) — координати огрубляються до району, точна адреса не публікується.

### 3.6 Маршрути памʼяті

- Кураторська сутність `memory_route` — впорядкована послідовність `place` через `memory_route_place.seq_order`.
- Режим «Пройти маршрут»: карта послідовно фокусується на кожній точці з описом, як гід-екскурсія; прогрес-бар кроків.
- Публікується через CMS, потребує статусу `published` (модуль CMS).

### 3.7 QR-фізичний міст (модель Inheart)

- Кожен `place` типу `memorial`/`monument`/`burial` отримує короткий редіректний URL (`memorial.gov.ua/p/{short_code}`) для друку на QR-табличці.
- Сканування веде напряму на картку місця з фокусом карти на цій точці — не на загальну карту.

### 3.8 3D/термінал і панорами (за наявності ресурсів партнера)

- Опційний 3D-рельєф (`terrain-rgb` тайли) для ландшафтного контексту місць боїв.
- 360°-панорами меморіалів підключаються через `place.cover_media_id` → `media_asset.kind = panorama`, відкриваються в модальному вʼювері (Pannellum) — технічно той самий компонент, що й у Museum.

## 4. Продуктивність і деградація

- Мобільні/слабкі пристрої: замість live MapLibre-рендеру — статичне превʼю карти (растрове зображення з маркерами) з кнопкою «Відкрити інтерактивну карту», прогресивне підвантаження повного рендеру.
- Векторні тайли кешуються на CDN; regeneration тайлів — асинхронна задача при публікації нового `place` (інвалідація конкретного тайлу, не всього кешу).
- Обмеження запиту `GET /places`: `bbox` обовʼязковий на високих zoom-рівнях, щоб уникнути вивантаження всієї бази точок одним запитом.

## 5. Приватність і чутливість

- `sensitivity_level`: `0` — публічно точно, `1` — огрублені координати (центр району замість точної точки), `2` — приховано з публічної карти (видно тільки `admin`/`archivist` в CMS).
- Шар `frontline_segment` публікується виключно на основі офіційно розсекречених історичних даних — не поточної оперативної обстановки. Юридичний рев'ю перед публікацією кожного датасету лінії фронту.

## 6. Дані і API (посилання)

- Схема: `place`, `memory_route`, `memory_route_place`, `defender_place_role`.
- Ендпоінти: `GET /places` (GeoJSON, `bbox`/`layer`/`date_from`/`date_to`), `GET /places/{id}`, `GET /memory-routes`.

## 7. Метрики успіху

- Час до першого змістовного рендеру карти (маркери видимі) — ціль &lt;2с на 4G.
- Частка сесій карти, що завершуються переглядом картки місця, — індикатор залучення.
- Кількість активних QR-сканувань на місяць (після встановлення табличок).

## 8. Ризики

- **Точність історичних геоданих** боїв часто приблизна — потрібен статус «орієнтовна локація» на картці замість хибної точності.
- **Продуктивність при тисячах точок** на області — обов'язковий навантажувальний тест кластеризації до релізу Beta.
