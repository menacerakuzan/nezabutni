# PRD · Модуль «Цифровий архів»

**Статус:** до розробки · **Версія:** 1.0 · **Залежності:** `docs/db/schema.dbml` (`media_asset`, `media_derivative`, `media_link`, `source`, `media_fixity_check`), `docs/api/openapi.yaml` (тег `Archive`)

## 1. Мета і межі модуля

Ядро доказовості платформи: документи, фото, відео, аудіо з повними метаданими, OCR/HTR-текстом, версіями, явними правами і постійними ідентифікаторами. Внутрішня концептуальна модель — **CIDOC CRM** (подія/учасник/місце), зовнішній обмінний формат — **EDM/Dublin Core**, перегляд — **IIIF**. Вибір підтверджено дослідженням: саме цей стек використовує Europeana для агрегації спадщини 2025–2026 (включно з пілотами IIIF Change Discovery API замість batch-експорту).

**Не входить**: сама UI-презентація в «зали» (→ Museum), відображення на карті (→ Map, лише посилання через `media_link`).

## 2. User stories

| # | Роль | Історія |
|---|------|---------|
| A1 | Дослідник | Хочу знайти всі документи з певним словом у розпізнаному тексті |
| A2 | Архіваріус (партнер) | Хочу масово завантажити 500 сканів з CSV-метаданими одним пакетом |
| A3 | Учитель | Хочу процитувати документ за постійним посиланням (PID), яке не зламається за 5 років |

| A5 | Юрист/DPO | Хочу бачити явний статус прав (rights statement) кожного обʼєкта перед публікацією |

## 3. Функціональні вимоги

### 3.1 Модель обʼєкта архіву

- `media_asset` — майстер-запис (незмінний оригінал, `master_uri` у WORM-бакеті, `storage_checksum` sha256).
- `media_derivative` — похідні (превʼю, IIIF-тайли, HLS для відео) — регенеруються, не потребують WORM.
- Метадані на базі Dublin Core + EDM: `title`, `description`, `provenance`, `rights_statement` (обовʼязкове поле, без значення за замовчуванням — публікація неможлива без явного статусу прав).
- `source` — привʼязка первинного джерела факту (документ, свідчення) до будь-якої сутності через `source.media_id`.

### 3.2 Конвеєр приймання (ingest pipeline)

```
Upload → вірусскан (ClamAV) → витяг EXIF/технічних метаданих
      → генерація похідних (превʼю, IIIF-тайли, HLS-транскод відео)
      → OCR/HTR (Tesseract для друкованого тексту; Transkribus/eScriptorium
         для рукописних листів і щоденників — окрема черга, повільніша)
      → мовна детекція → індексація в Elasticsearch (full-text по ocr_text)
      → AI-чернетка опису і тегів (ai_task, requires_human_review=true)
      → архіваріус вичитує й підтверджує → модератор публікує
```

Кожен крок — окрема задача в `ai_task`/черзі RabbitMQ, ідемпотентна, з ретраями. Помилка на будь-якому кроці не блокує показ обʼєкта в кабінеті партнера зі статусом помилки — не «зникає мовчки».

### 3.3 Пошук

- Повнотекстовий по `ocr_text` (`GIN`-індекс, `to_tsvector('ukrainian', ...)`), фасети по `kind`/`rights_statement`/датах.
- Підсвітка збігів у OCR-тексті з координатами слова на зображенні (для viewer) — метадані підсвітки зберігаються поруч з `ocr_text` у структурованому вигляді (не лише plain text).
- Пошук «схожих зображень» — окремий AI-модуль (див. PRD 06 AI Layer), використовує `embedding`.

### 3.4 IIIF-вʼювер

- `GET /media/{id}/manifest` віддає IIIF Presentation Manifest v3.
- Фронтенд-компонент: `OpenSeadragon`, спільний з модулем Museum (`packages/viewer`).
- Підтримка анотацій на зображенні (виділення обличчя/підпису/печатки) як IIIF Annotation.

### 3.5 Версії і незмінність

- Майстер-файл ніколи не перезаписується; заміна оригіналу (напр. знайдено якісніший скан) створює новий `media_asset` з посиланням `replaces_media_id` на попередній (поле додається в наступній ітерації схеми).
- `content_revision` фіксує зміни метаданих (не самого файлу) з diff і можливістю відкату.
- `media_fixity_check` — періодична (щомісячна) перевірка контрольної суми майстер-файлів проти збереженої, алерт при розбіжності (ознака пошкодження сховища).

### 3.6 Права і ліцензії

- Значення `rights_statement`: `CC0`, `CC-BY`, `CC-BY-SA`, `in-copyright-permission-granted`, `in-copyright-restricted`, `orphan-work` (за моделлю rightsstatements.org, сумісною з Europeana).
- Публічний API (`GET /archive/search`, `GET /media/{id}`) віддає лише обʼєкти зі статусом `published`; обʼєкти `in-copyright-restricted` доступні тільки автентифікованим дослідникам з обґрунтуванням запиту (адмініструється вручну на MVP).
- За замовчуванням для нових завантажень від державних партнерів — `CC0`/`CC-BY` (модель Smithsonian Open Access), обмежувальний статус — усвідомлений виняток, не дефолт.

### 3.7 Пакетне завантаження партнером (Bulk ingest)

- `POST /partner/collections/{id}/ingest` — multipart: файли + CSV-метадані (мапінг на Dublin Core поля).
- Відповідь `202` з `IngestBatch.id`, прогрес відстежується через `GET /partner/collections/{id}/ingest/{batchId}` (лічильник `processed_files`/`total_files`, масив помилок по конкретних файлах).
- Ліміт розміру пакету на MVP: 500 файлів / 5GB за раз, з можливістю кількох послідовних пакетів.

## 4. Довгострокове збереження (preservation)

- Формати збереження (TIFF/PDF-A) відокремлені від форматів доставки (JPEG/WebP/MP4) — конвертація відбувається на етапі похідних, майстер зберігає оригінальний формат завантаження.
- Геореплікація MinIO між двома дата-центрами (details — DevOps PRD/розділ 15 Master Plan).
- Політика зберігання: майстер-файли не видаляються ніколи (окрім юридично обов'язкового видалення за запитом субʼєкта даних — окремий процес із DPO).

## 5. Дані і API (посилання)

- Схема: `media_asset`, `media_derivative`, `media_link`, `source`, `media_fixity_check`, `collection`, `collection_media`.
- Ендпоінти: `GET /archive/search`, `GET /media/{id}`, `GET /media/{id}/manifest`, `POST /partner/collections/{id}/ingest`.

## 6. Метрики успіху

- Частка обʼєктів з заповненим `rights_statement` до публікації — має бути 100% (hard constraint, не метрика для покращення).
- Пропускна здатність OCR-черги (обʼєктів/годину) достатня для обробки накопиченого фонду партнера за &lt;1 тиждень.
- Успішність fixity-перевірок — 100%, будь-яке відхилення — інцидент P1.

## 7. Ризики

- **Обсяг рукописних матеріалів** (листи, щоденники) вимагає HTR, що повільніше і дорожче за звичайний OCR — плануємо окрему пріоритезовану чергу і бюджет на Transkribus API або self-hosted eScriptorium.
- **Юридична невизначеність прав** на архівні фото з відкритих джерел (соцмережі родин) — потрібен чіткий процес отримання явної згоди перед публікацією, не «мовчазна згода за замовчуванням».
