# PRD · Модуль «Онлайн-музей»

**Статус:** до розробки · **Версія:** 1.0 · **Залежності:** `docs/db/schema.dbml` (`exhibit`, `exhibit_defender`, `collection`, `story`, `story_defender`, `partner`), `docs/api/openapi.yaml` (тег `Museum`)

## 1. Мета і межі модуля

Іммерсивний шар над тими самими даними: тематичні «зали»-експозиції, 3D-експонати, панорами, кураторські «історії памʼяті» з таймлайнами. Медіа-фундамент — **IIIF Presentation API v3** (deep-zoom перегляд документів/фото, повнотекстовий пошук по OCR-шару) за прикладом стеку Europeana, підтверджено дослідженням.

**Не входить**: власне зберігання і метадані медіафайлів (→ Archive), керування колекціями партнера (→ Partner cabinet, частина CMS).

## 2. User stories

| # | Роль | Історія |
|---|------|---------|
| E1 | Громадянин | Хочу «пройти» тематичну експозицію як віртуальну виставку з текстом, фото і 3D-предметами |
| E2 | Куратор (музей-партнер) | Хочу зібрати експозицію з готових блоків без участі розробника |
| E3 | Учитель | Хочу вбудувати (embed) експонат чи історію в навчальний матеріал |
| E4 | Дослідник | Хочу переглянути 3D-модель предмета з усіх боків і прочитати повні метадані провенансу |
| E5 | Відвідувач з VR-гарнітурою | Хочу зайти в панораму меморіалу в іммерсивному режимі |

## 3. Функціональні вимоги

### 3.1 Структура контенту

- **Колекція** (`collection`) — набір медіаобʼєктів партнера за ознакою (напр. «Особисті речі 128-ї бригади»).
- **Експозиція** (`exhibit`) — курований «зал»: впорядкована послідовність блоків (`blocks: jsonb`), кожен блок — один з типів: `text`, `media`, `quote`, `model3d`, `panorama`, `map_embed`, `timeline_embed`.
- **Історія памʼяті** (`story`) — лонгрід з окремим полем `timeline: jsonb` (масив `{date, title, media_id, body}`), незалежний від структури «зали», більш редакційний формат (аналог статті).

### 3.2 Кураторський конструктор (частина CMS, описана тут з погляду музейної логіки)

- Блоковий редактор типу Notion: перетягування блоків, живий preview.
- Кожен блок посилається на існуючі сутності архіву (`media_asset`) або реєстру (`defender`) — куратор не завантажує файли повторно, а обирає з архіву через пошук.
- Версіонування: кожна зміна експозиції — новий `content_revision`, можливість відкату.

### 3.3 3D-експонати

- Формат зберігання: `glTF/GLB` (веб) з `USDZ`-похідною для AR Quick Look на iOS.
- Рендер: `<model-viewer>` веб-компонент як типовий кейс, `three.js` для кастомних сценаріїв (анотації на моделі, підсвічені точки з описом деталі).
- Оптимізація: Draco-стиснення геометрії, KTX2-текстури, лінива підгрузка моделі тільки при скролі до блоку.
- LOD (рівні деталізації) для мобільних — низькополігональна версія за замовчуванням, high-res за запитом.

### 3.4 Панорами і VR

- 360°-панорами: `Pannellum` або `Marzipano` (equirectangular JPEG/WebP), той самий компонент, що використовується для панорам місць на карті (спільний з модулем Map).
- VR-режим: WebXR як progressive enhancement — за наявності гарнітури зʼявляється кнопка «Увійти у VR», без гарнітури панорама працює як звичайний 360°-перегляд мишею/тачем.

### 3.5 Гігапіксельний зум документів

- `OpenSeadragon` + IIIF Image API для сканів документів і фотографій високої роздільної здатності всередині блоку `media`.
- Той самий вʼювер, що використовується в модулі Archive для карток документів — спільний компонент `packages/viewer` (див. Frontend Architecture).

### 3.6 Звʼязок з реєстром

- `exhibit_defender` і `story_defender` — expo/історія може посилатися на кількох захисників; на профілі захисника відображається блок «Згадується в експозиціях/історіях».

### 3.7 Embed-віджети

- Публічний iframe-embed для окремого експонату/історії з мінімальним UI, для вставки на сайти шкіл/медіа.
- Атрибуція і посилання на джерело обовʼязкові в embed-версії (юридична вимога rights statement).

## 4. UX і продуктивність

- Прогресивне завантаження: текстові блоки рендеряться відразу (SSR), важкі медіа (3D/панорами) — лінива підгрузка з skeleton-заглушкою.
- Клавіатурна навігація між блоками експозиції (стрілки/Tab), читання скрін-рідером у логічному порядку блоків.
- `prefers-reduced-motion`: вимикає авто-обертання 3D-моделей і плавні переходи між блоками, замінює на миттєві.

## 5. Дані і API (посилання)

- Схема: `exhibit`, `exhibit_defender`, `collection`, `collection_media`, `story`, `story_defender`, `partner`.
- Ендпоінти: `GET /exhibits`, `GET /exhibits/{slug}`, `GET /stories`, `GET /archive/{id}/manifest` (IIIF, спільно з Archive).

## 6. Метрики успіху

- Середній час перебування на сторінці експозиції — індикатор іммерсивності.
- Кількість експозицій, опублікованих партнерами самостійно (без участі розробників) — індикатор успіху кураторського конструктора.
- Частка 3D-моделей, що завантажуються за &lt;3с на 4G.

## 7. Ризики

- **Обсяг 3D-контенту** вимагає ресурсів для фотограмметрії — на MVP-етапі покладаємось на партнерів-музеї з готовими моделями, власне сканування — Фаза 2.0.
- **VR/AR — нішева аудиторія** на старті; прогресивне покращення гарантує, що базовий досвід не залежить від наявності гарнітури.
