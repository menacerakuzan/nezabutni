# Меморіал — Технічна документація

Ця папка — робочі специфікації, похідні від [Master Plan v1.0](../.claude/CLAUDE.md) (артефакт з повним 23-розділовим планом). Джерело істини для розробки.

## Структура

- **`prd/`** — детальні PRD по модулях (готові до розбиття на беклог):
  1. [`01-defenders-registry.md`](prd/01-defenders-registry.md) — реєстр захисників, верифікація, майстер подання
  2. [`02-interactive-map.md`](prd/02-interactive-map.md) — GIS-карта, шари, кластеризація, маршрути памʼяті
  3. [`03-online-museum.md`](prd/03-online-museum.md) — експозиції, 3D, панорами, кураторський конструктор
  4. [`04-archive.md`](prd/04-archive.md) — ingest-конвеєр, IIIF, OCR/HTR, права і збереження
  5. [`05-cms-moderation.md`](prd/05-cms-moderation.md) — блоковий редактор, workflow, черга модерації, RBAC
  6. [`06-ai-layer.md`](prd/06-ai-layer.md) — AI-можливості, гардрейли, семантичний пошук
- **`db/schema.dbml`** — повна ER-модель (DBML) — імпортувати напряму на [dbdiagram.io](https://dbdiagram.io/d) для візуалізації.
- **`api/openapi.yaml`** — контракт REST API (OpenAPI 3.1) — узгоджений зі схемою БД, готовий для генерації типізованого клієнта та документації (напр. через Redocly/Swagger UI).

## Порядок читання

1. Master Plan (артефакт) — стратегія, дизайн-система, roadmap.
2. `db/schema.dbml` — словник сутностей.
3. `prd/*.md` — детальні вимоги по модулях (посилаються на схему і API).
4. `api/openapi.yaml` — точний контракт для фронтенд/бекенд команд.

## Наступні кроки

- Розбити кожен PRD на епіки/тікети в трекері (Jira/Linear).
- Figma-макети на дизайн-системі «Свіча» (токени описані в Master Plan, розділ 07).
- Юридичний рев'ю обробки ПДн (розділ 16 Master Plan) перед стартом Ф0.
